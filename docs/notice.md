# 待機察覺

**目標**：觀眾走進範圍時，09 光紗的世界要「察覺」到有人，表現成**世界感受到人**，而不是**人影響世界**。
**架構位置**：輸入層（Main 既有的 `Viewer`、`MousePersonSource`、`Choreography`）＋渲染層（光紗 `Assets/_Project/Idle/`、察覺 `Assets/_Project/Notice/`）。
**位置**：直接在 `Scenes/Main.unity` 做，不另開場景。09 光紗已搬進 Main（PR #2），畫面不變。
**分支**：從 `main` 開 `feat/idle-notice`。

## 規則

- 待機畫面**不畫身影**：只能從世界的反應推測有人在。試片不理想時，可以加回一點能辨識身影的元素
- 判斷標準：不知道原理的觀眾，**靜音並排**看待機與有觀眾進場的錄影，能指出「大概從第幾秒開始不一樣」
- 世界的反應要有延遲、有主見（可以只反應一部分，也可以不理）；不是位置對位置的即時變形，也不限於 09 既有的事件語彙
- 世界只知道：有沒有人、大概位置、待了多久，以及一個慢半拍的影子（2026-11-04 放寬，給尾流用：影子到現在位置的線段就是尾巴）；不知道精確位置與動作
- 反應主要發生在主體光紗（占畫面大面積處）；倒影可以參與，但倒影區塊的面積不得超過主體
- 範圍：單人，從進場到離開。多人與交會之後再談

## 時間軸（初始值，全部放 Inspector，看實測再調，也可能分更多段）

| 階段 | 時間 | 世界做什麼 |
|---|---|---|
| 察覺延遲 | 進場後約 0.5 秒 | 還沒反應 |
| 屏息 | 約 6 秒，與下面重疊 | 光紗的速度**緩緩**降到約 25%（1.5 秒）→ 維持 1.5 秒 → 緩緩恢復（2.5 秒）。人離開就立刻開始恢復，所以路過的人只換來一小段變慢 |
| 路過 | 停留 < 3 秒 | 只有屏息（甚至不理） |
| 停留 | 3–10 秒 | 在速度還慢的時候，周圍粒子開始讓出空間，之後速度恢復、空間繼續撐開；脈衝煞在邊緣外 |
| 久留 | > 10 秒 | 空間撐得更大 |
| 餘韻 | 離開後，長度與停留時間成正比 | 空間慢慢合攏；凝結與飛向鏡頭在餘韻結束後才恢復，交換的視覺效果慢慢回來 |

反應從 0 升到滿約 4 秒。順序是：**光紗變慢 → 讓出空間 → 流速恢復**。

## 現在的設計（第六輪：繞流 Flow）

2026-11-04。第五輪看起來仍像「一塊黑色區域把粒子擋住」，不是粒子繞著邊緣走。原因在架構：Clear 是**每幀從頭算的靜態變形**（粒子位置只由當下的人物場決定），粒子流進來時被立刻重新擺放，所以永遠是同一個洞；關掉 alpha（Rim Burn Guard 0、站著不動、沒有暗帶）洞也還在。第六輪改成**人物影響既有粒子的運動**，Clear 原封不動保留，Parts 二選一做 A/B。

- **每顆粒子多記兩個值**：`noticeOffset`（偏移，螢幕半高）與 `noticeVelocity`（偏移的速度），是 `Idle_Veil.vfx`、`Idle_Reflect.vfx` 的自訂屬性（Vector2），在 Update 之間保存，出生時為 0。**待機位置照舊每幀無狀態算出**（光紗、交換、凝結、顏色、透明度、大小、景深都不動），最後位置 = 待機位置 + 偏移。不用內建 `velocity`：Update 的 Integration 是 Euler，任何 block 寫 `velocity` 就會自動補一個 `position += velocity * dt`，跟我們的偏移重複積分
- **每次更新**：`target = 察覺 × 強度 × h(s) × (避讓 × 往外 + 滑行 × 順流分量 × 沿邊) − 偏移 / 回復時間`；`速度 += (target − 速度) × (1 − e^(−dt / 反應時間))`；`偏移 += 速度 × dt`（半隱式）。dt 是 VFX 自己的 `Delta Time (VFX)`，不經 C#
  - **避讓**：沿身體邊緣法線往外，0.1 螢幕半高/秒。`h(s)` 在邊緣最大、邊緣外 0.6 處歸 0、往身體內 60% 半寬處歸 0，所以中間不推，穿過去的粒子讓中間不會空
  - **沿邊滑行**：0.3 螢幕半高/秒。方向**以粒子原本的流向為準**：取光紗中線在螢幕上的切線（遠景塵埃幾乎不動，用世界的左→右），只保留它沿著邊緣的那一份（`tanh(沿邊分量 / 0.25)`）。正面撞上的流幾乎不滑，從旁邊經過的整份順著滑；上揚的光紗從上面繞、下沉的從下面繞。後備：流向正對邊緣時，加一點「上半往上、下半往下」（0.15）讓它選邊，不是主規則
  - **回復**：彈簧一直在，回復時間 3 秒（至少 1.5 倍反應時間，阻尼比 ≥ 0.6）。人走後察覺退去，粒子延遲回到原處
  - **察覺 Awareness**：`NoticeState.aware`，進場 0.5 秒後在 1 秒內平滑升到 1（`Aware Rise`），離開後在餘韻時間內退去，重新進場從當下的值接續。**人物範圍固定**（Width Stay / Height Stay，不再從 0 長大），只有強度在變。每顆粒子在這段上升裡的不同時間醒來（最多晚 60%），所以是一部分先察覺
  - **各層不同**：每條光紗自己的強度與反應時間（近景故事光紗 0.6–1.2 秒、強度 0.6–1；遠景塵埃 1.4 秒、強度 0.35），再依當下景深連續變化（最遠 ×0.4 強度、慢 1.5 倍），每顆粒子的強度再慢慢呼吸 ±45%。**沒有固定比例隨機忽略人物**
  - 身體形狀沿用 Clear 的膠囊、扭彎、寬度起伏、傾斜、中心飄移；**不改透明度、顏色、大小**，沒有遮罩、沒有暗帶、沒有額外光效
- **穩定性**：dt 夾在 0–0.1 秒；|偏移| ≤ 0.8（超過時截斷並去掉往外的速度）、|速度| ≤ 0.8；NaN 會讓那顆粒子歸零重來（儲存的屬性壞了會永遠壞）。人物位置突變、快速進出時改變的是力，偏移與速度連續跟上，粒子不跳位；只有手動切換 Clear／Flow 會跳
- **測試用開關**：NoticeSensor 的 `Flow Terms`（只在 Flow 開時有效）：Both／Avoid Only（只避讓＋回復）／Slide Only（只滑行＋回復）。`IdleMirror` 的 `Fixed Seed`（0 = 每次隨機）、`People` 物件上預設關閉的 `ScriptedPersonSource`（固定路徑：5 秒進場 → 站到 17 秒 → 3 秒橫移 → 站到 24 秒離開 → 看恢復）
- **數值檢查**：[notice-flow-check.js](notice-flow-check.js) 是 `Notice_Flow.hlsl` 的 JS 副本，`node docs/notice-flow-check.js` 可重跑：線性部分在各 dt 的過衝 ≤ 6%；整個人物場在 144 / 60 / 30 / 10 Hz 與 5–100 ms 亂跳的 dt 下都沒有 NaN、偏移與速度不超上限、離開 20 秒後平均偏移降到停留時的 0.3%（亂跳 dt 1%）、穩定後各幀率的平均偏移差 ≤ 9%；人物瞬移＋快速進出 10 次仍連續有界；站 60 秒沒有粒子卡在上限、身體內保留約 51% 的待機粒子（變稀、不空）；與 HLSL 的 20 個常數一致；直直朝中間來的粒子在三種模式都會被偏轉。**這些只說明積分是穩的，不代表看起來像繞流**，繞流、壓縮、尾流要在 Game View 判斷（見「還沒驗證」）
- 2D 預覽（模擬器）的觀察：第一版讓流向「整片決定往上或往下滑」，絲帶正面撞上身體的直面時會停住再垂直滑走，像撞牆後的硬拐角；改成只保留順流分量後彎曲變平順。只開避讓時主要是上游減速、擠壓；只開滑行時是順流向彎；兩個都開最像繞流
- **第一次 Play：完全看不出推擠**（2026-11-04）。接線與保存都查過沒問題（屬性有被判定為讀寫並儲存），是強度太保守：第一版避讓 0.07、滑行 0.14，偏移只有約 0.1 螢幕半高，而 Unity 的光紗是約 0.3 寬的鬆散帶子，0.1 的位移淹在裡面；模擬器把光紗加寬到接近 Unity 後也一樣看不出來。現在的數字（避讓 0.1、滑行 0.3、範圍 0.6、順流判斷 0.25、回復 3 秒、呼吸 ±45%、上限 0.8）在寬光紗的模擬裡光紗會整條從上或下繞過，身體內約剩一半粒子。上限從 0.6 放到 0.8：0.6 時近景光紗繞過身體會被卡在上限最久 4 秒。`Flow Terms` 的 Show Offset 會把被移動的粒子染紅，用來確認 Flow 真的在動、作用在哪裡

## 第五輪（Clear，仍在，A/B 用）

2026-11-04。第四輪的長方形被看成「debug 碰撞框、硬挖空」，第五輪把它改成**柔性的存在場**：核心、殼、尾流三層融在一起，看不出分界。只動 `Notice_Clear.hlsl` 的形狀與推擠、`NoticeState` 的尾流；脈衝、對焦、繞圈程式都還在，但驗證期關掉（Main 的 Parts 只勾 Clear、Orbit Share Stay / Long 設 0）。

- **核心**：直立膠囊（圓角半徑 ≈ 半寬，略微呼吸），仍有第四輪的扭彎、傾斜、寬度起伏、中心飄移。**不再清到 0，也沒有台階**：離中線 d 的粒子被移到 `dp(d)`；d 小於半寬 / 3 的粒子散開填滿整個核心，所以核心密度 = (離中線 / 半寬)^2（`Notice_Core_RAMP`）：中線上幾乎沒有，往邊緣緩升到 1；更外面的粒子被推出核心。另外有一小部分粒子（`Notice Core Keep`，預設 0.05，遠景 ×3）固定留在原地，越靠中線越暗（×0.45）越小（×0.8）。**取代第二～四輪「裡面一顆都沒有」**：那時是留太多（遠景塵埃、300 顆）看不出分別，現在是中間很空、往邊緣漸漸有。（第一版是「全部推到邊緣外、只有 6% 留下」，審查與數值檢查都發現邊緣有約 30 倍的密度台階，會讀成輪廓線，所以改成緩坡）
- **殼**：推出核心的粒子在邊緣外堆成略密的一圈（峰值約 1.5 倍；`Rim Softness` 0.25 時影響範圍約 4 倍半寬；沒另外加亮度，`Rim Burn Guard` 照舊）。推擠方向 = 往外一步 + **沿邊切線一步**（`Notice Deflect`，切線步 / 往外步，限制在 0–1.5）。切線方向跟著高度翻轉：上游（左）側上半往上、下半往下，粒子沿膠囊滑向兩端；背風（右）側滑動只有 50%、推擠 85%，方向相反（流被收回來）。左右用 smoothstep 平滑過渡，膠囊頂端沒有接縫。每顆粒子各自差 ±25%，**遠景只滑 50%、推 80%、核心留的粒子多 3 倍**，所以各層不一樣
- **尾流**：`NoticeState` 多一個更慢的跟隨者（`Wake Lag` 2.5 秒，不會比 `Viewer Lag` 快），從觀眾到它的線段是尾巴（最長 1.2 螢幕半高）。尾巴上有一條**暗帶**（寬度同膠囊、越遠越淡、只在觀眾後方），帶內的粒子變暗（最多 ×0.4）變小（×0.85）。**只改權重、不改位置**：第一版在尾巴上疊 2–3 個較弱的推擠副本，數值檢查發現副本互相干涉成一排洞，不是連續的尾巴，所以改成暗帶。觀眾站定後影子追上，尾長 < 0.04 時暗帶消失；離開走原本的餘韻
- 數學用腳本檢查過（[notice-field-check.js](notice-field-check.js)，`node docs/notice-field-check.js` 可重跑）：核心中線密度從 0.05 緩升到約 1（相鄰 0.05 格最大差 0.32）、殼的密度峰值約 1.5 倍、位移沒有折疊（Jacobian 最小 0.72，Deflect 到 1.5 仍有 0.57）、尾巴沿線的可見密度是一條連續的緩降
- **還沒做、下一輪**：邊緣更不規則、隨時間流動（現在只有第四輪原有的扭彎、傾斜、起伏）；殼的流向假設光紗由左往右（沒有依實際流向）；側面中段（y ≈ 0）的切線滑動為 0，只是往外退，滑動出現在上下半；尾流只改亮度與大小、沒有位移，看樣後再決定要不要真的推開

## 第四輪（形狀與核心被第五輪取代，其餘仍在）

第一輪試了五個方案：脈衝最明顯、螺旋醜、對焦有趣但不能當主角、倒影沒感覺（倒影占畫面太小）、彎向你幾乎看不到。第二輪改成讓出空間；第三輪、第四輪看過截圖再調：

- **主角：讓出空間（Clear）**。粒子離開人周圍的一塊**人形大小的直立圓角長方形**，在邊緣堆出一圈較亮較密的邊，光紗照樣流過與繞過它
  - 長方形約是人身方框的 1.2 倍（停留）到 1.5 倍（久留）：半寬 0.22 → 0.27、半高 0.76 → 0.95（螢幕半高為單位）。**不規則、每秒都在變**：邊緣被幾道慢波扭彎（`Notice Edge Ragged` 0.12）、寬度沿高度起伏（±25%）、整體微微傾斜擺動（約 ±6°）、寬高各自起伏 ±12%、圓角大小也在變、中心慢慢飄。不畫身影，沒有頭肩
  - 推擠沿著離邊緣最近的方向：離開中線 d 的粒子移出 `A * (1 - smoothstep(0, L, d))`，`L = A / Rim`。空間內沒有粒子，L 以外不動；邊緣自然壓縮變密，並只取消 20% 的密度（`Notice Rim Burn Guard`）。第四輪把邊緣放柔（`Notice Rim Softness` 0.55 → 0.4）：影響範圍更長，周圍的光紗從更遠處就開始彎開，不像擋住的黑塊。長方形中線兩側的粒子會分往左右，像光紗被撥開
  - **所有深度層都把空間清乾淨**（第二輪遠景只讓 30%，結果空間裡還留著一堆遠景塵埃）；遠景只是參與繞圈的比例少（30%）
- **繞圈的粒子（orbiters）**：邊緣附近的粒子（停留 30%、久留 55%，吸引範圍 0.45 / 0.65）從光紗被慢慢「拉」過來，沿著長方形外圈打轉，像好奇的生物，大多貼著邊緣。每顆有自己的方向、速度（約 0.15–0.6 螢幕半高／秒）、離邊緣的距離，並在那個距離上下晃；只有約 0.3% 偶爾鑽進長方形裡一小段，其餘一律不進邊緣內側（第三輪 3% 讓裡面有幾百顆，不夠乾淨）。用「在周長上的比例」定位，所以長短邊速度一致、空間撐大時也平順。離開後隨權重下降散回光紗
- **脈衝（Pulse）**：環形亮帶從遠處往空間收，掃進來約 1.6 秒（比第二輪快）、**煞在被擠開的粒子外緣**（離邊緣 1.6 步，1 步 = 0.35 螢幕半高），停下後淡出；經過後的粒子微顫。**沒有心跳**：第二輪初版有「到達時邊緣瞬間再開 18%」，看起來像心跳，已拿掉
- **對焦（Focus）**：輔助。邊緣與繞圈粒子清晰、遠處柔和
- **安靜（Quiet）**：有人在場時世界安靜下來專心看人
  - **凝結、飛向鏡頭**：新事件不再開始（開始時間落在安靜窗口內的事件被跳過），進行中的自己跑完；人走了、餘韻結束後才恢復。這兩種事件沒有永久效果，所以只需要記最近兩段窗口
  - **交換**：搬動是永久的（系統每幀從開機重播所有事件），不能跳過，否則之後忘掉窗口，被跳過的事件會在重播時補發、上千顆粒子同時換光紗。所以只做**視覺上的安靜**：發光、變粗、飛行時的增亮在約 5 秒內平順淡掉（`Quiet Rise`），光紗恢復均勻，人走後慢慢回來。粒子換光紗仍在背景悄悄發生，但看不出來
- 刪掉：Bend、Knot、Mirror（想法留在點子池，程式在 git 歷史）
- 數學用腳本檢查過：周長函數的點全部落在邊上、等長步進；推擠（含傾斜、變寬、扭彎）後空間內沒有粒子殘留（15 萬個樣本 0 個）

## Inspector 可調欄位

**Hierarchy 的 `Notice` 物件（NoticeSensor）**：Play 時可以直接改，立刻生效。

| 欄位 | 預設 | 作用 |
|---|---|---|
| Parts | Flow（Main） | 複選：Clear 讓出空間、Pulse 脈衝、Focus 對焦、Flow 繞流（勾了 Flow 就只跑 Flow，其他三個不跑）。全不勾 = 原本的待機 |
| Flow Terms | Both | **測試用**，只在 Flow 開時有效：Both／Avoid Only（只避讓）／Slide Only（只滑行）／Show Offset（Both，加上被移動的粒子染紅，0.2 螢幕半高全紅）。回復一直都在 |
| Show Debug | 開 | 左上角文字（含 aware）與黃色十字 |
| Settings: Notice Delay | 0.5 | 進場到世界開始有反應（秒） |
| Settings: Aware Rise | 1 | 察覺從 0 升到 1 的時間（秒），從 Notice Delay 之後開始；離開後在餘韻時間內退去 |
| Settings: Hush Rise / Hold / Fall | 1.5 / 1.5 / 2.5 | 變慢的時間：緩降、維持、緩復（秒） |
| Settings: Hush Slow | 0.25 | 最慢時的速度（1 = 正常，0.1 = 幾乎停住） |
| Settings: Passing Max | 3 | 停留幾秒以下算路過 |
| Settings: Long After | 10 | 停留幾秒以上算久留 |
| Settings: Ramp Time | 4 | 反應升到滿要幾秒 |
| Settings: Afterglow Per Dwell / Min / Max | 0.5 / 1 / 20 | 餘韻長度 = 停留秒數 × 前者，夾在後兩者之間 |

## 怎麼接的

```text
Viewer A/B/C、MousePersonSource -> PersonTracker -> NoticeSensor (Scripts/)
   NoticeState: 有沒有人、x、y、停多久 -> 世界時鐘、stay、longStay、viewerX、viewerY、quiet、最近兩段安靜窗口
每幀寫進 Idle Veil、Idle Reflect（14 個 Notice 輸入，含 Wake X / Y、Aware；另有 18 個形狀欄位在 Veil 上調、倒影自動複製）與 Idle Fly（6 個）
Idle Veil、Idle Reflect 另有一個 Delta Time (VFX) 節點接到 noticeDt，兩個自訂屬性 noticeOffset / noticeVelocity
-> Idle_Veil.hlsl
     IdleVeil / IdleVeilReflect：讀出偏移與速度 -> Idle_Core -> 寫回（用 VFX_USE_NOTICEOFFSET_CURRENT 包起來，因為 Idle_Fly 也編譯這個檔但沒有這兩個屬性）
     Flow 開：Notice_Flow (Notice/Notice_Flow.hlsl)；否則偏移歸 0，Idle_NoticeBody -> Notice_Body (Notice/Notice_Clear.hlsl)
     兩者都在「不得低於地平線」與倒影翻轉之前改世界裡的粒子，倒影自動跟著翻出來（倒影自己存一份偏移，輸入相同，算出來也相同）
     Idle_Cond / Idle_Fly：開始時間在安靜窗口內就不開始；交換的視覺效果乘上 (1 - quiet)
```

- **Notice 物件的 Parts 可複選**：None＝與原本的待機逐像素相同（世界時鐘不接管）；Clear／Pulse／Focus／Flow 各一個位元（1 / 2 / 4 / 8，`Notice Mode` 輸入就是這個位元遮罩；Flow 開時 Flow Terms 再加 16 不避讓或 32 不滑行）。Main 現在是 Flow
- 輸入：Play Main，**關掉 Choreography**，滑鼠左鍵點一下＝觀眾進場（畫面上有彩色方框），拖曳移動，右鍵移除。世界只跟第一個人。`NoticeSensor` 用相機把人的位置投影成螢幕 (x, y)；Game View 左上角的文字與黃色十字顯示世界認為觀眾在哪、現在是哪個階段（`Show Debug`）
- 世界時鐘：Parts 不是 None 時，`IdleVeil`／`IdleVeilReflect`／`IdleFly` 把粒子的 `age` 改成 `Notice Clock`，屏息時整個世界一起變慢；安靜窗口也用這個時鐘
- `NoticeState` 是純邏輯，有 EditMode 測試（`FlowMirror.Tests` 共 50 個，含顏色交換、尾流與察覺，全過）
- **Flow 的接線（第六輪加的）**：自訂屬性要先在 graph 的 `m_CustomAttributes` 宣告（每個一段 `VFXCustomAttributeDescriptor`），Custom HLSL 只看**入口函式本身**寫到的 `attributes.xxx` 決定要讀寫哪些屬性，所以讀寫寫在 `IdleVeil` / `IdleVeilReflect` 裡、`Idle_Core` 只拿參數。VFX 的 Init 會把每個要儲存的屬性設成預設值 0，Update 再從 buffer 讀回來，所以偏移在幀與幀之間保存。`notice-vfx-check.js` 多檢查三件事：兩個屬性有宣告成 Vector2、`_noticeDt` 接到 Delta Time (VFX)、沒有 HLSL 寫 `attributes.velocity`。改 `.vfx` 前的版本備份在 git（31c0b97）
- 新增 VFX 輸入屬性用腳本複製 `Run Seed` 的接線，不手動拖線。**坑**：新節點若沒被加進 graph 的 children 清單，Unity 匯入時會判定「無效連結」，**自動重存檔並把連結清掉**；要先確認三份清單（graph children、block input slots、parameter info）都有，再匯入。匯入後用 `HasFloat` 確認屬性存在。**第二個坑（第五輪踩到，整個畫面的粒子都不見）**：`Idle_Veil.hlsl` 入口函式的簽名只要有語法錯誤（例如 `void` 和函式名黏在一起），Unity 匯入時就找不到那個函式，會悄悄把 Custom HLSL 區塊改指向 `IdleFly`、砍掉其他輸入槽並**存檔**；之後把 HLSL 修好也不會恢復，而 `HasFloat` 仍然是 true。每次匯入後跑 `node docs/notice-vfx-check.js`（檢查區塊呼叫的函式、輸入槽順序與簽名一致、每個槽都連到屬性），並看 `git diff --numstat` 的 `.vfx` 幾乎只有新增行。壞了就從上一個好的 commit 還原 `.vfx` 再重新接線

## 還沒驗證（要在 Unity Play 裡看）

**Flow（第六輪）的視覺驗收**：用 Fixed Seed＋ScriptedPersonSource 錄同一段，Parts 切 Clear／Flow、Flow Terms 切三種各錄一次。有慣性不等於自然繞流，下面每一項都要在連續錄影裡看到，不能只靠數值檢查：

- A（0–5 秒，沒有人）：與原本的待機一樣
- B（進場後前 2 秒）：沒有突然變化；一部分光點先開始偏轉，其餘陸續跟上
- C（約 5 秒）：粒子順著原本的流向沿人物邊緣滑過，上游略微擠壓，不是撞牆後的硬拐角
- D（約 10 秒）：人物附近是柔和、不完整、隨時間變化的低密度區，**不是固定的人形空洞**；近景反應明顯、遠景較弱
- E（橫移、離開後）：後方延遲回填；離開後粒子慢慢回到原本的流，不是瞬間恢復
- 擠壓處有沒有過亮（只能調強度，不加遮罩）；三種 Flow Terms 是否讀得出差別

**Clear（第五輪）**：
- 膠囊夠不夠「不規則、會變」（下一輪要加強）、核心邊緣有沒有被看成輪廓、殼那圈讀不讀得出「被擠開、滑開」、會不會過曝；尺寸（1.2 / 1.5 倍）會不會太大；尾流的暗帶讀不讀得出「剛離開的地方還空著」
- 繞圈粒子的疏密、數量、速度；被拉過來時路徑是直線，偶爾可能穿過空間
- 脈衝是否停在被擠開的粒子外緣、夠不夠快
- 安靜：交換的發光是否真的淡掉；凝結、飛向鏡頭在人進場後是否不再開始新的；人走後是否恢復
- 對焦當輔助時是否加強而不搶
