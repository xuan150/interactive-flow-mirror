# Light Ecosystem — Particle Field Prototype

## 0. 專案基本資訊

- 引擎：Unity 6（6000.3.15f1）
- Render Pipeline：URP 3D
- 螢幕輸出：1920 × 960（2:1）
- 畫面類型：即時生成式互動藝術
- 目前階段：Idle／無人待機
- 開發目標：建立一個獨立運作、具有透明層次與粒子聚散生命週期的視覺系統
- 後續需求：接受人體追蹤座標，讓既有粒子世界對人物產生局部反應

本階段不實作人體辨識、人體剪影、手勢或多人互動。

### 最重要的要求

畫面主體必須由**大量獨立光點共同構成具有連續性的抽象形態**。

不使用固定線條、大片透明 Mesh 或預設幾何圖形作為主要視覺骨架。

粒子應具備局部凝聚、流動、分離與重新組織的能力。

---

# 1. 核心視覺設計

## 1.1 主視覺

整體使用接近黑色的深靛藍背景。

畫面包含 3 組主要粒子聚落，每組由數千個微小粒子組成。粒子不是均勻散布在全畫面，而是集中在具備不同大小、形狀、方向與密度的區域。

三組聚落不需要彼此連接，也不能強制生成固定圓環、球體、水平波浪或人形。

聚落由粒子的空間分布形成。

每組聚落應具備：

- 不規則的延展方向
- 至少一個密度較高的區域
- 逐漸變稀疏的外緣
- 局部透空區域
- 多個深度層次
- 可以持續變化的形態

重要：粒子之間不繪製連接線。

## 1.2 視覺層級

由後至前分為四層：

### A. Background

深靛藍色背景。

允許極低對比的大尺度漸層變化，但初期不加入流體、星空或具象雲霧。

### B. Structure Particles

畫面主體。

大量粒子組成局部連續的抽象結構。

具有明確的共同流向、疏密差異與聚合行為。

### C. Ambient Particles

少量低亮度、較分散的微粒。

負責補充深度與空間細節。

不可成為全畫面均勻星點背景。

### D. Energy Highlights

少量亮度較高的粒子群。

只在局部聚落活躍、粒子密度增加或能量傳遞時出現。

不得預先放置固定光核。

# 2. 粒子系統資料結構

建議使用 Compute Shader 儲存及更新 GPU 粒子。

每個粒子至少保有以下資料：

```hlsl
struct Particle
{
    float3 position;
    float3 velocity;
    float3 restPosition;

    float seed;
    float phase;
    float intensity;

    uint clusterId;
    uint layerId;
};
```

其中：

- position：目前位置
- velocity：目前速度
- restPosition：所屬結構的參考位置
- seed：決定個體差異的固定值
- phase：動態相位
- intensity：發光強度
- clusterId：所屬聚落
- layerId：所在深度層

實作時需確認 C# 與 HLSL 的結構記憶體配置一致。

# 3. 聚落形態生成

這是整個 Prototype 最重要的系統。

## 3.1 不使用純隨機散點作為主體

不接受以下做法：

1. 在整張畫面隨機放置粒子。
2. 對每顆粒子加入 Noise。
3. 用 Bloom 讓粒子看起來很漂亮。

這種方式無法保證出現連續、具有主次的視覺結構。

## 3.2 使用有組織的粒子分布

建議每個聚落先建立一個低維度的變形參考域。

可以將粒子表示為：

- u：沿著聚落主要延展方向的位置
- v：在聚落橫向分布的位置
- w：深度偏移

由以下映射取得世界位置：

```text
position = ClusterMapping(u, v, w, time)
```

ClusterMapping 必須能同時控制：

- 聚落中心位置
- 主要延展方向
- 局部彎曲
- 橫向擴張與收縮
- 深度厚度
- 局部扭轉與不規則變形

粒子使用不同的 u、v、w 與 seed，避免排列成規則網格。

這個結構只是控制粒子分布的參考域，不是要繪製一片可見的 Mesh。

## 3.3 聚落連續性

單一聚落內，相近參考座標的粒子應具有相關的運動趨勢。

不能讓所有粒子每幀完全獨立地隨機移動。

同時也不能讓整個聚落像一片硬板，同步旋轉或平移。

建議將粒子運動拆成：

```text
Particle Motion
= Structural Motion
+ Local Flow
+ Individual Variation
```

Structural Motion：控制整體形態。

Local Flow：讓粒子在結構內部流動。

Individual Variation：提供微小的不規則性。

三者使用不同的強度及時間尺度。

# 4. 粒子聚散生命週期

每組聚落具有四種連續狀態。

## State A：Dispersed

粒子分布較寬，局部密度較低。

仍需保有可辨識的整體結構，不可以全部變成均勻隨機散點。

## State B：Gathering

聚落中的部分區段逐漸收縮。

粒子間距縮小，局部密度提高。

注意：

- 不把所有粒子吸向單一點。
- 不讓整個聚落同時縮成一顆球。
- 只讓部分區域收斂。
- 其他區域保持原本的低密度結構。

## State C：Active

局部密集區域形成明確視覺焦點。

此時：

- 粒子仍持續移動。
- 局部亮度提高。
- 少量亮度脈衝可沿結構流動。
- 聚落不停止變形。
- 不生成大型實心光球。

## State D：Releasing

聚落局部逐漸舒展。

密度降低，亮度回落。

粒子重新沿著參考域分布，而不是直接瞬間重置到初始座標。

### 生命週期要求

三個聚落使用不同的時間相位。

不得讓所有聚落同步聚集或同步散開。

不同聚落可以同時處於不同狀態。

狀態切換需要平滑插值。

---

# 5. 待機動畫時間尺度

使用以下初始時間配置：

| 動態類型 | 建議時間尺度 |
|---|---|
| 個別粒子微幅流動 | 持續 |
| 局部結構扭轉與彎曲 | 3–8 秒 |
| 一次聚落收縮／舒展 | 8–16 秒 |
| 主要構圖焦點遷移 | 20–40 秒 |

這些是初始測試值，不是固定循環長度。

不同系統必須具備獨立的時間控制。

不得只使用同一個 Sin(Time) 驅動全部效果。

# 6. 透明感實作

透明感不等於使用一片透明材質。

這個 Prototype 的透明感由以下因素組成：

1. 粒子的局部密度差
2. 粒子的亮度與 Alpha 差異
3. 多層深度分布
4. 部分區域保留低密度空隙
5. 明亮聚落與暗部之間的對比

## 初始渲染建議

採用 URP 相容的透明 Billboard 粒子渲染。

優先使用不透明度較低、邊緣平滑的圓形粒子 Sprite。

可以使用：

- Alpha Blending 作為基礎粒子層。
- 少量 Additive Blending 作為高亮粒子層。

不建議所有粒子都使用強 Additive，否則密集處容易過曝。

### 粒子尺寸

以 1920 × 960 Game View 測試：

- 主體粒子：約 1–3 px
- 環境微粒：約 0.5–1.5 px
- 少量高亮粒子：約 2–4 px

以上為視覺目標尺寸，需要依攝影機與粒子材質實際換算。

使用以下初始色彩：

| 用途 | Hex |

| 背景 | #080D1B |
| 深藍 | #233A79 |
| 冷藍 | #65A7EB |

| 粉紫 | #D9A5DB |
| 暖粉 | #F1B8C5 |
| 暖金 | #FFD5A5 |

### 色彩分布原則

- 不要讓每個粒子完全隨機選擇顏色。
- 同一聚落內的相近區域應有相關色彩。
- 允許局部冷暖色自然過渡。
- 高光使用低飽和度的暖白或冷白。
- 保持深色背景與低亮度區域。
- 初期先固定曝光，最後再加入 Bloom。

# 8. GPU 與 Unity 架構

## 8.1 推薦組件

```text
LightEcosystem
├── ParticleSimulation.compute
├── ParticleRender.shader
├── ParticleFieldController.cs
├── ClusterController.cs
├── ParticleRenderController.cs
└── DebugSettings.cs
```

檔名為建議，並非強制。

## 8.2 Compute Shader

負責：

- 粒子初始化
- 結構位置計算
- 速度與位置更新
- 局部聚散參數
- 粒子動態相位
- 聚落強度
- 亮度權重

## 8.3 Rendering Shader

負責：

- Billboard 粒子繪製
- 粒子尺寸
- 顏色
- Alpha
- 邊緣柔化
- 局部 HDR 高光

不應直接負責主要粒子聚散的運動邏輯。

## 8.4 C# Controller

負責：

- 建立與釋放 GraphicsBuffer
- 設定 Compute Shader 參數
- Dispatch 模擬
- 提交渲染命令
- 管理聚落狀態
- 提供 Inspector 調整參數

不得在每幀建立新的大型 GPU Buffer。

場景停止、物件停用或銷毀時，必須正確釋放 GPU 資源。

# 10. 實作里程碑

## M1：靜態粒子結構

建立 3 個由粒子構成的抽象聚落。

驗收：

- 不是隨機粒子牆。
- 不是固定球體或環。
- 可以看出局部連續性。
- 具有明顯疏密與留白。
- 關閉 Bloom 仍能辨識形態。

未通過之前，不進行下一階段。

## M2：結構動態

讓聚落緩慢變形。

驗收：

- 粒子與結構同時具有運動。
- 不只是整體平移或旋轉。
- 不出現突然跳動。
- 不變成規則水平波浪。
- 運動具有連續性。

## M3：聚散循環

加入 Gathering、Active、Releasing。

驗收：

- 某個局部區域可以逐漸變密。
- 其他區域仍保留低密度結構。
- 聚集後可以自然舒展。
- 沒有瞬間重置。
- 三個聚落不完全同步。

## M4：透明與光影

加入顏色、Alpha、局部高光。

驗收：

- 聚落具備透空與重疊層次。
- 不變成實心發光塊。
- 不出現大片過曝白光。
- 冷暖色彩能自然過渡。

## M5：完整待機

加入少量低亮度環境微粒及非常柔和的背景色彩變化。

驗收：

- 背景不搶走主體。
- 整體畫面不空洞。
- 可以持續運行至少 60 秒。
- 視覺焦點會隨時間逐漸轉移。
- 無明顯動畫循環切點。

# 11. Agent 工作限制

請嚴格遵守以下流程。

1. 先檢查現有 Unity URP 專案設定。
2. 不修改既有光絲 Prototype。
3. 建立獨立測試場景。
4. 先完成 M1 並提供可運行結果。
5. 未完成 M1 驗收，不得自行實作 M2–M5。
6. 不得為了讓畫面更漂亮而自行加入大量 Bloom、透明薄膜或固定線條。
7. 所有影響形態、動態、密度及高光的主要參數都必須可在 Inspector 調整。
8. 發現現有架構不適合時，先說明技術原因與替代方案，不得未經說明就改成完全不同的視覺技術。
9. 不得把 AI 概念圖當成逐像素重現目標。
10. 每完成一個里程碑，應保留可回退版本。

# 12. 最終設計原則

我們追求的不是一片隨機粒子，也不是漂亮的粒子特效。

而是一個由大量微小光點組成、能夠持續重新排列的透明視覺生態。

粒子的密度與共同流向形成抽象結構；聚合與舒展產生生命感；局部高光與柔和色彩建立視覺層次。

待機畫面必須先獨立成立，才能進入人體互動開發。

未來人體進入時，應改變原有系統的局部粒子分布與流向，而不是另外疊加一套人體特效。
